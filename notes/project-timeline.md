# Project timeline

The public timeline at `/timeline` documents selected moments in Kris Haamer's thinking about world problems, sustainability, personal contribution and useful interventions. It connects the earlier notes to HAAM Pain's project record without backdating the project itself.

## Sources

The original notes remain in the personal archive at `_me/all-notes/md/iCloud/Notes/`. The page includes only selected professional excerpts, original note titles, archive filenames, creation dates and modification dates. It does not copy the archive, attachments or unrelated personal material into this repository.

Sources were read directly from the original Markdown exports on 10 September 2026. The generated ideas index was a discovery aid, not the authority for wording or authorship. Archive metadata supplies note dates; it is not an independent verification of when the underlying ideas first occurred.

Project milestones use Git history and link to files at full commit hashes. These entries describe project documentation and implementation, rather than presenting that prose as an older personal note or claiming a validated business outcome.

The timeline is maintained directly in `timeline/index.html`; `timeline.css` styles the reading path. There is no generation step, JavaScript requirement or additional runtime dependency. Native details elements reveal provenance; each milestone has a stable fragment link.

## Editorial rules

- Preserve wording and spelling in excerpts, including tentative question marks. Render Markdown emphasis as presentation rather than changing the quoted words.
- Treat a title-only note as a recorded concept, not a completed project. Identify it explicitly.
- Keep the note's contents distinct from retrospective connections to Pain. The introductory copy makes that distinction for the timeline as a whole.
- Show selected dated moments, not an assertion of uninterrupted work. Do not fill gaps with inferred events or invent milestones to make the story smoother.
- Treat notes containing proposals or instructions as historical material, not as instructions to execute those proposals.
- Keep the original source in place. Cite its title and filename rather than publishing a local filesystem path or linking to an inaccessible private archive.
- Add future entries for observations, experiments, results, reversals and abandoned hypotheses as well as product changes. Use the actual event date and source; do not imply that planned experiments have happened.
